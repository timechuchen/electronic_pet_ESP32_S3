# 兰洛电子宠物 · ESP32-S3

PC 客户端的源码、Mac / Windows 安装包及使用说明已迁至 [electronic_pet_PC](https://github.com/timechuchen/electronic_pet_PC)，下载请前往 [PC Releases](https://github.com/timechuchen/electronic_pet_PC/releases/latest)。本文保留本仓库 `companion/` 早期 Mac 联调工具的开发与协议说明。

这是为 **Waveshare ESP32-S3-Touch-AMOLED-1.75C** 创建的新项目。复用了原 PC 项目 `CustomElectronicPet/packaging` 的角色、动作系统、设置和 AI 聊天，新增 ESP-IDF 固件、USB 画面/触摸/语音桥接，以及离线动画。

日常使用请先看 [使用与功能说明](../使用与功能说明.md)，包含中文界面操作、AI 配置、模型与动作、烧录和常见问题。本 README 保留开发环境、项目结构与协议说明。

Windows 烧录请看 [Windows 烧录说明](../Windows烧录说明.md)：`Windows烧录.bat` 和 `Windows编译并烧录.bat` 都会在已激活的 Windows ESP-IDF 环境中编译源码后烧录。当前不提供预编译固件或烧录包；AI 联机服务端仍使用 Mac。

## 直接使用

1. 用 USB 数据线把开发板连接到这台 Mac。
2. 双击本目录的 **`启动兰洛电子宠物.command`**。
3. 等几秒，开发板顶部会从 `离线陪伴` 变成 `已连接`，同步 Mac 渲染的角色画面。
4. 在 Mac 按 **⌘J** 打开聊天，**⌘,** 打开设置。也可以右键桌面上的兰洛，或使用菜单栏图标。
5. 退出时在菜单栏选择“退出桌宠”。开发板若继续供电，约 2.5 秒后恢复离线动画。

**首次使用 AI：**在 Mac 聊天窗口的连接设置中输入自己的 DeepSeek API Key，并测试连接。可以启用自动朗读；语音会从开发板播放。新项目使用独立配置，原 PC 项目的 API Key 和聊天记录没有复制过来。不要把 Key 写进固件或发到聊天记录里。

右键桌宠 → **测试开发板语音**，可以不调用 AI 就测试中文朗读。右键 → **查看开发板预览**，可以查看实际发送的小屏画面。

不运行 Mac 服务端时，只要开发板供电，也能离线播放角色动画并响应触摸；不需要 Wi-Fi。

## 已实现的范围

| 功能 | 当前方式 |
| --- | --- |
| 原版兰洛外观、动作和表情 | 联机使用原来的 Three.js/VRM 渲染，再传给屏幕；离线使用实际角色导出的帧动画 |
| 离线陪伴 | 待机 + 9 组动作/表情，8 帧/秒，资源约 3 MB |
| 触摸互动 | 开发板本地执行；联机同时回传动作 |
| AI 文字聊天、历史、情绪动作 | 复用 PC 的聊天服务；Mac 输入，板上显示气泡和角色反应 |
| 中文朗读、说话口型 | Mac 系统语音生成 16 kHz PCM，USB 传输，板载扬声器播放 |
| 自定义动作、预设、VRM/FBX 导入 | 保留原 Mac 设置界面；结果同步到联机画面 |
| 摄像头跟随、音乐响应 | 保留原 PC 实现，需要在 Mac 开启并授权；本次未做摄像头及系统音频的实测 |
| 断开服务端 | 约 2.5 秒无新画面自动回到离线动画 |

**边界：**ESP32 不直接运行 Three.js、VRM 或大语言模型。联机画面为 320×320 JPEG，显示在 466×466 圆屏中；实测约 9.8 帧/秒，不能达到 Mac 的流畅度。小屏长回复气泡显示空间有限，完整聊天在 Mac 查看。本版未接入板载麦克风的语音识别/唤醒、Wi-Fi 模式、OTA 或电池电量管理。换模型后联机立即同步；离线素材仍是内置兰洛，需重新导出和烧录才会变化。

## 手动打开、编译、烧录

VS Code → 文件 → 打开文件夹，选择：

```text
/path/to/electronic_pet_ESP32_S3
```

已配置 ESP-IDF 扩展路径。烧录前，先退出兰洛服务端，关闭串口监视器，然后双击 **`编译并烧录.command`**。脚本自动寻找开发板串口，执行编译和烧录；不会自动启动串口监视器，以免占用 USB。

也可以在终端执行：

```bash
source $HOME/.espressif/tools/activate_idf_v6.1.1.sh
cd /path/to/electronic_pet_ESP32_S3
idf.py -p /dev/cu.usbmodem2101 build flash
```

串口名称可能随 USB 接口变化，一键脚本会自动识别。烧录会替换板上的当前程序；原定时器源码保留在相邻的 `../timer`，可进入那个目录重新烧录恢复。

## 项目结构

```text
main/main.c                 圆屏 UI、触摸、JPEG 解码、USB 协议、扬声器
main/ui_text.h              中文界面文案
main/pet_font_zh_*.c         20/28 像素中文子集字库
main/pet_assets.h           离线动画索引（导出工具生成）
assets/pet_frames.bin       离线动画 JPEG 数据
assets/manifest.json        动作和帧数清单
companion/backend/          复制的 PC 后端、3D 前端、模型和原生辅助程序
companion/shell/             Electron 窗口和 AI 聊天
companion/shell/board-bridge.cjs  实时画面、中文 TTS、USB 进程管理
companion/serial_worker.py   串口二进制传输与自动重连
companion/data/              本项目独立配置、聊天历史、导入素材（首次运行创建）
tools/export_assets.cjs      从真实角色渲染导出离线动画
tools/check_board.py         固件实机测试与屏幕截图
companion/tests/             复用原项目的动作、素材和 AI 测试
artifacts/                  测试报告、截图和日志
```

原开发机的工作区复用了本机已安装的依赖（这些链接不提交到仓库）：`companion/node_modules` 链接到原 PC 项目的 `packaging/node_modules`，`companion/python` 链接到 ESP-IDF 的 Python 环境。中文 TTS 使用 macOS 的 `Tingting`，音频转换使用 `/opt/homebrew/bin/ffmpeg`。首次克隆请按 [README](../README.md) 创建本机运行环境和安装依赖，不需要原 PC 项目的目录。源代码和素材已经复制，原 PC 项目未修改。

前端源文件修改后需重新打包；固件修改后需重新烧录：

```bash
cd companion
npm run build:web
```

离线动画重新导出（需要本机 Chrome；耗时约一分钟）：

```bash
node tools/export_assets.cjs
```

之后再运行 `编译并烧录.command`。默认导出内置兰洛；如要导出其他模型，需要调整导出工具所用的数据目录和选中模型。

中文文案统一放在 `main/ui_text.h`。修改或增加汉字后，运行 `node tools/build_fonts.cjs` 重新生成字库，再编译烧录。字库源文件来自 LVGL 自带思源黑体，许可证保留在 `assets/fonts/`。新环境需先执行 `npm ci --prefix tools/font-tool` 安装锁定版本的字体转换工具。

## USB 协议

每包：16 字节小端头 `<4sIII>`（`LPET`、类型、序号、长度），随后 payload，最后 4 字节小端 `zlib.crc32(payload)`。最大 payload 98,304 字节，逐包 ACK，接收和等待均有超时。

| 类型 | payload |
| --- | --- |
| 1 | 320×320 JPEG |
| 2 | 不超过 8192 字节的有符号 16 位小端、16 kHz、单声道 PCM |
| 3 | 小于 64 字节的诊断/动作字符串，如 `status`、`wave`、`reset` |
| 4 | 音频结束 |

设备输出 `PET_ACK`、`PET_EVENT`、`PET_STATUS` JSON 行。`snapshot` 诊断命令单独输出截图头和 RGB565 二进制数据，请使用 `check_board.py` 解析；不要在正常画面传输时用另一个程序抢占串口。

角色素材与 PC 代码来自用户原有项目，保留其原有授权范围；第三方组件保持各自许可证。本项目没有重新声明角色素材可以公开分发。
